# 连接器字段自动命名

状态：implemented
类型：bug-fix
Owner：web/src/utils/connector_field_names.js

## 问题

飞书字段选择后逐项命名增加配置负担，直接使用字段 ID 不易理解。

## 决策

### 实现方案

配置弹窗在勾选新字段时生成名称：常见 CRM 名称使用固定英文映射，英文列名规范化，未知中文使用稳定字段 ID。重名添加字段 ID 区分，并避开调用协议保留名。已有映射保持原值，避免改变现有 consumer；手动修改折叠为高级选项。名称与字段类型沿用现有 JSON 保存链路。

## 替代方案

拒绝要求所有用户手工命名；不使用模型翻译，避免依赖、随机性与延迟。

## 后果

未知中文字段仍以 ID 区分；默认生成的名称可以在高级选项修改。不会自动重命名既有映射。

词表覆盖客户状态、标签、行业、规模、跟进记录、商机金额等当前 CRM 通用字段。用户可点击“优化默认参数名”将已选字段的历史默认 ID 名称批量优化到本次表单草稿，同时更新对应类型和业务键引用；手工名称保持原值，保存前可审阅。保存后依赖旧参数名的调用方需要使用新名称。

## 验证

unit 验证常见字段、未知中文、英文规范化、已有映射保持及重名和保留名处理。浏览器验证勾选生成、默认无需输入和高级修改入口；实际飞书凭据与权限不由命名逻辑变更。
